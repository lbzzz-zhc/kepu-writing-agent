# 链接入库使用说明（免上传）

> 目标：以后不必导出文档，**直接把公众号文章链接丢给我就行**。
> 工具：`tools/wechat_ingest.py`（已同步到技能 `kepu-writing-agent/scripts/`）

---

## 一、你怎么用（一句话版）

把链接粘过来，说一句「把这篇入库」即可。例如：

```
https://mp.weixin.qq.com/s/xxxxxxxxxxxx  把这篇入库
```

我会自动完成：抓正文 → 提标题/日期/公众号名 → 判文体 → 生成 KB1 语料文件 → 更新语料清单。

日期抓不到或不准时，**我会问你，不会自己猜**。文体判不准时同理。

---

## 二、四条路径（按顺序自动尝试）

| 路径 | 做法 | 适用 | 你要做什么 |
|---|---|---|---|
| **A 自动抓取** | 直接请求文章页提取正文 | 公开可读的公众号文章 | 只给链接 |
| **B 复制粘贴** | 你在浏览器打开文章 → 全选复制正文 → 粘给我 | 抓取失败、需验证、文章已删 | 复制粘贴一次 |
| **C 导出文件** | 导出 docx/html 后入库 | 图片承载信息多、要保留版式 | 导出一次 |
| **D 批量** | 一次给多条链接 | 补语料时最快 | 一次贴一批 |

**A 不成功时我会明确告诉你失败原因**，不会拿残缺内容凑数——这是设计如此。

---

## 三、入库后的文件长什么样

```
10_知识库/01_历史语料库/KB1-STD-202608-02_卸妆那点事.md
```

头部字段（自动生成）：

```yaml
id: KB1-STD-202608-02
title: 卸妆那点事|皮肤状态越来越差，会不会是妆没卸干净？
published: 2026-08-26        # 抓不到会写"待确认"
word_count_net: 1941
cjk_count: 1317
genre: STD
byline: 待确认
account: 待确认
original_mark: 待确认
diluted: false
parse_quality: 完整
images: 5
source_url: https://mp.weixin.qq.com/s/xxxx
fact_usable: false           # ← 恒为 false，硬约束
```

`fact_usable: false` 的含义：**这篇只能用来学风格，永远不能当作这次写作的事实来源。** 这是防"旧数据自动继承"的第一道闸。

---

## 四、三条纪律（自动执行，不需要你操心）

1. **单篇新样本不改规则**：新文章只进 KB1；只有当某个新特征在 **≥3 篇**出现、且与现有规则冲突时，我才会提议修订 KB2；
2. **抓取失败就报失败**：不产出残缺语料污染风格库；
3. **限速、只抓本人文章**：不做批量高频请求。

---

## 五、典型问答

**Q：别人公众号的文章能入库吗？**
A：技术上可以，但**不该**。语料库是用来学"你的风格"的，混入他人文章会把风格带偏。他人文章只能作负样本，且必须标 `diluted: true` 单独存放。

**Q：抓不到日期怎么办？**
A：我会问你。日期决定"风格漂移"判断，宁可问一次。

**Q：一次能贴几篇？**
A：一次 10–20 条也行，但**建议先跑 3 条确认口径**，再批量。

**Q：图片会丢吗？**
A：会。抓取只拿文字。图片承载的信息（如数据表）不会进语料——这正是 `parse_quality` 字段存在的原因，图片多的文章我会标"疑似残缺"并提示你。

---

## 六、技术备注

- 依赖：Python 标准库，无需安装任何第三方包；
- 抓取标识：使用移动端微信 UA（贴近正常阅读请求）；
- 诊断：`--dry-run` 只诊断不写文件，适合先探路；
- 失败码：`2` = 网络/HTTP 失败｜`3` = 反爬或正文过少｜`1` = 参数错误。
