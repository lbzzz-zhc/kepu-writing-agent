## 一、这是什么

个人微信公众号科普写作智能体：从已发表推文提炼**可验证的个人风格**，产出"像我、说人话、科普严谨"的推文。
技术路线：**知识库 + 工作流 + 系统提示词，不微调模型。**

## 三、关键决策与纪律

**架构决策（D1–D11，改需记版本）**
- **D1 = A 强隔离**：写作节点只读 KB2 规则卡，KB1 原文不进写作上下文
- D5 每次检索 5–10 篇同文体语料，仅取结构骨架｜D7 标题与结构为内部产物（满足"不先出提纲"）
- D9 三道硬闸：G1 检索隔离 · G2 事实完备 · G3 重复检测（连续 12 字）
- D10 资料不足固定暂停话术，不写占位稿

**四条不可违反的纪律**
1. KB1 只提供风格，**永不提供事实**（`fact_usable: false` 恒定）
2. 写作节点**不读历史原文**，只读规则卡 —— 机制化防洗稿
3. 成稿里每个标准号/限值/日期都必须能在**本次事实底稿**找到 🟩 记录
4. 三审独立执行，**只有否决权、没有放行权**

**规则升级纪律**：单篇新样本只进 KB1、不改规则；同一新特征在 **≥3 篇**出现且与现规则冲突才修订 KB2；规则频率一律以 `tools/style_report.py` 实测为准（`corpus_digest.py` 提供逐篇特征）。

**KB2 改动后的三步**（少一步就会提示词与库不一致）：
```bash
python tools/style_report.py 10_知识库/01_历史语料库 --md 10_知识库/02_风格规则库/风格体检报告.md
python tools/build_site.py --project . --out docs --sync-prompt   # 同步注入区
python tools/build_site.py --project . --out docs && python tools/build_writer.py --project . --out docs
```

3. **线上页面调本地服务需 CORS**：服务端已补 `Access-Control-Allow-Origin` / 预检 OPTIONS / `Allow-Private-Network`。
   若浏览器仍拦，**最稳是直接用本地地址** `http://127.0.0.1:8787/writer.html`（同源，无跨域）。

## 七、自我纠错留档（勿重犯）

1. **不要对中文正文做 NFKC 归一化** —— 会把全角标点压成半角，破坏标点风格特征（实测原文全角逗号 1159 : 半角 1）。
2. **docx→md 的 `![](data:image...)` 必须清除** —— 否则混入正文使字数虚高 200–300 字。
3. **不要凭少量样本断言规则，且样本扩大后必须复核** —— "标准引用三段式 4/4"实为样本偏差（全量 6/13）；"来源模块 92%"扩样后降到 STD 88% / HEALTH 50%。**规则必须带文体/变体限定。**
4. **测试接口时不要把结果写回项目文件** —— 曾把 KB1 指向临时目录但统计缓存路径写死，导致真实统计被覆盖成 1 篇。现缓存路径由 KB1 推导。
5. **判图注必须保守，不能用"短 + 紧邻图片"** —— 首次清洗时误删 191 处，其中包含 `选购注意事项`、`认清标准`、`温度稳定性` 等真实小标题（微信排版里小标题后紧跟图片很常见）。改用三条强特征后降到 40 处，小标题全部保住。
6. **改函数返回类型时要查所有调用点** —— `html_to_lines` 改为返回 `(lines, stats)` 后，`_generic_body` 仍被按列表使用过。
7. **命令行里写含 `\s` `\S` 的正则会被 shell 转义干扰** —— 曾导致"字段明明存在却匹配不到"的假故障。复杂正则改用脚本文件，或用 `[ ]` 等不转义写法。

## 八、设计取舍备忘

- **七步流水线**：变体判定 → 事实底稿 → 生成正文 → 事实审校 → 风格审校 → 合规自查 → 按意见修订。写作方只拿规则卡+事实底稿，三审方只拿成稿。
- **为什么"来源模块"不能写死名字**：实测「内容参考」12 篇 /「内容来源」5 篇，写死会变成机械复制。
- **为什么竖线标题不能当通用规则**：全库 9/23（39%），但**系列内 9/9（100%）** —— 是"系列命名"特征，非全库特征。
- **「专家建议」不是禁用词**：作者在 2 篇中使用，只需保证依据可溯源。
