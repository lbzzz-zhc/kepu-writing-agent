## 四、关键决策与纪律

- **D1 = A 强隔离**：写作节点只读 KB2 规则卡，KB1 原文不进写作上下文
- D9 三道硬闸：G1 检索隔离 · G2 事实完备 · G3 重复检测（连续 12 字，已实现 `/api/dupcheck`）
- D10 资料不足固定暂停话术，不写占位稿

**四条不可违反**：① KB1 只给风格不给事实（`fact_usable: false` 恒定）② 写作节点不读历史原文
③ 每个标准号/限值/日期都要能在本次事实底稿找到 🟩 ④ 三审独立，只有否决权没有放行权

**改 KB2 后必跑三步**（少一步提示词就与库不一致）：
```bash
python tools/style_report.py 10_知识库/01_历史语料库 --md 10_知识库/02_风格规则库/风格体检报告.md
python tools/build_site.py --project . --out docs --sync-prompt
python tools/build_site.py --project . --out docs && python tools/build_writer.py --project . --out docs
```

## 八、自我纠错留档（勿重犯）

1. **不要对中文正文做 NFKC 归一化** —— 会把全角标点压成半角（原文全角逗号 3460 : 半角 37）。
2. **docx→md 的 `![](data:image...)` 必须清除** —— 否则字数虚高 200–300 字。
3. **不要凭少量样本断言规则，扩样后必须复核** —— "三段式 4/4"实为样本偏差（全量 6/13）；"来源模块 92%"→扩样后 81% 且要按文体分。**规则必须带文体限定。**
4. **统计缓存路径要与页面读取一致** —— `features_path()` 曾多写一层 dirname 落到工程外，造成"写 A 读 B"，工作台永远显示旧数据。
5. **判图注必须保守** —— 用"短+紧邻图片"误删 191 处真实小标题（`选购注意事项`/`认清标准`/`温度稳定性`）。
6. **改函数返回类型要查所有调用点** —— `html_to_lines` 改成返回元组后，`_generic_body` 仍按列表用。
7. **命令行里的 `\s` `\S` 会被 shell 转义干扰** —— 造成"字段存在却匹配不到"的假故障。
8. **替换 HTML 用 `replace(..., 1)`** —— 页面 JS 的"导出 Word"模板含 `</head>`，全量替换会污染它。
9. **规则/阈值不许硬编码** —— 曾出现页面文案 v0.2、知识库已 v0.3；现全部由 KB2 解析 + `--sync-prompt` 生成。
10. **入库必须重建页面** —— 页面数据烤进 HTML，只重算统计不重建，工作台看不到新语料。

## 九、设计取舍备忘

- **来源模块名不能写死**：实测「内容参考」33 篇 /「内容来源」5 篇，写死会变机械复制。
- **竖线标题不是通用规则**：全库 9/79（11%），但系列内 9/9 —— 是"系列命名"特征。
- **比喻几乎不用**：全库仅 5/79（6%）；推进靠设问（76%）+ 举例（33%）。
- **作者角色 = 解释者 + 提醒者**：消费者 67%、建议句 89%、留余地 82%、情绪词仅 22%。
- **「专家建议」不是禁用词**：作者用过，只需依据可溯源。
