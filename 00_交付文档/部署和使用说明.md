# 部署和使用说明

> 2026-09-12 更新：新增**在线网页版**（展示台 + 写作台），见文末「七、在线网页版」。

## 一、文件放哪里

### 本地工程目录（组织、版本管理、模板）
`科普写作智能体/` —— 已建好，13 → 20 个文件，含 4 个知识库分区、工作流、测试集。

### 知识库（供智能体检索）
在资料库里建 4 个分区，与本地目录同名对应：

| 资料库分区 | 上传什么 | 注意 |
|---|---|---|
| KB1 历史语料库 | 已发布推文全文（15–40 篇） | 每篇头部加 `fact_usable: false` |
| KB2 风格规则库 | S2 生成的规则卡 | 写作时的唯一风格依据 |
| KB3 本次事实资料库 | 每次写作一个子目录：原始资料 + 事实底稿 | 每次写作新建，不跨篇复用 |
| KB4 评估与禁用库 | 禁用清单、评分卡、误用台账 | 审校时读取 |

**分工建议**：本地目录当"工作台"（模板、版本、草稿），资料库当"检索源"（智能体按分区检索）。只用一个也行，但别两边各改一份。

## 二、系统提示词放哪里

- **完整版** → `20_工作流/系统提示词_完整版.md`，整段粘进智能体的「系统提示词 / 人格设定」框；
- **压缩版** → `20_工作流/系统提示词_压缩版.md`，短上下文时替换。

粘贴后记得把第 10 节的 `<<<KB2_RULES_START>>>` 区间，在 S2 完成后填上规则卡内容。

## 四、每次写新文章，最少要提供什么

**三样，缺一不可**：
1. **一个明确选题**（不是一串）；
2. **本次事实资料**——标准原文、官方发布、权威报道、检测数据（放 KB3）；
3. **文体**（或让智能体判定）。

**可选**：目标字数（默认 1500–2500）、目标读者、是否要配图/竖版。

**它会拒绝开工的情况**：没有本次事实资料、同文体规则不足、支点事实无来源。这时它会输出暂停提示并向你要料——**这是设计如此，不是故障**。

## 五、新文章发布后怎么更新风格库

```
发布 → 导出全文 → 头部填元数据 → 存入 KB1 → 更新语料清单.csv
                          ↓
              仅当出现"新的稳定特征"时，才考虑动 KB2
```

**判断标准**
| 情况 | 动作 |
|---|---|
| 新的生活化案例、新口语习惯、新收尾方式 | **只加样本**到 KB1，不动规则 |
| 同一新特征在 **≥3 篇**新文章中出现，且与现规则冲突 | **修订规则**：更新 KB2，记版本号与生效日期 |
| 某规则近 6 个月 0 命中 | **降级**为 T 级，或移入 KB4 观察区 |
| 单篇出现的新写法 | 不动。记为观察项，不写进规则库 |

**为什么要这么严**：一两篇文章的偶然写法不是风格；过早写成规则，智能体会把"偶发"当"习惯"，越写越不像。

## 六、常见问题

**Q：能不能直接让它读历史文章写新文章？**
A：不能。D1 选定强隔离，写作环节只读规则卡。这是防洗稿的机制保障。

**Q：它写出来的数字我怎么放心？**
A：成稿每个数字都能在本次事实底稿找到 🟩 记录。要核对时说「把事实底稿一起给我」。

**Q：为什么它老是停下来要资料？**
A：宁可停下要料，也不编。这是你在核心原则里定的规则。

**Q：什么时候需要重做风格手册？**
A：风格发生明显漂移（如换了栏目定位、写作状态变化）时，按近 12 个月语料重跑一次 S2。

## 七、在线网页版

### 两个页面

| 页面 | 用途 | 地址 |
|---|---|---|
| **index.html 展示台** | 看规则、查语料、复制系统提示词 | 部署链接根路径 |
| **writer.html 写作台** | 填选题 + 资料 → 七步流程 → 出成稿 | 部署链接 `/writer.html` |

两页可互相跳转。均为**零依赖单文件**，双击本地文件也能打开。

### 写作台怎么用

1. 点「显示 / 隐藏」展开**模型设置**，填三样：接口地址、模型名、API Key → 保存 → 测试连接
   - OpenAI 兼容格式，可用 DeepSeek / 通义 / 智谱 / Kimi / OpenAI 等
   - **API Key 只存在你本机浏览器（localStorage），不上传任何服务器**
2. 填**选题**（一个主题）
3. 把**本次事实资料**（标准原文 / 官方发布 / 权威报道 / 检测数据）粘进去 —— **必须填**，不填会直接停工
4. 点「开始生成」，页面按七步依次执行，每步可展开看中间产物
5. 成稿出来后点「复制成稿」

### 七步为什么是七次独立请求

写作方只拿到「规则卡 + 事实底稿」；三审方只拿到「成稿」，**不共享对话历史**。
所以三审是真的上下文隔离，不是同一对话里自己查自己 —— 这正好补上了「三审降级」的缺口。

### 跨域问题怎么处理

浏览器直连模型接口时，若对方没开跨域，会报跨域错误。两种解法：

```bash
# 方式一（推荐）：起本地小服务，页面与接口转接一起来
python tools/writer_server.py            # 默认 http://127.0.0.1:8787
# 然后浏览器打开 http://127.0.0.1:8787/writer.html
# 并在模型设置里勾选「走本地代理端口」
```

```bash
# 方式二：仍用线上页面，但勾选「走本地代理端口」并让本地服务在跑
python tools/writer_server.py --port 8787
```

本地服务只监听 127.0.0.1，不对外网开放；请求由本机发出，因此没有跨域问题，Key 也不经过第三方服务器。

### 页面刷新（知识库更新后必做）

```bash
python tools/build_site.py   --project <工程根目录> --out <工程根目录>/docs
python tools/build_writer.py --project <工程根目录> --out <工程根目录>/docs
```

**规则表或语料更新后，重跑这两条命令再重新部署**，否则网页与知识库脱节。

## 八、写作台的两个进阶功能（需本地服务）

浏览器不能读写磁盘，也不能跨域抓取 `mp.weixin.qq.com`，所以下面两件事由本机小服务代劳。

先启动：

```bash
python tools/writer_server.py            # 默认 http://127.0.0.1:8787
```

启动后可在写作台点**检测本地服务**确认连通（正常会显示"当前语料 N 篇"）。

### 功能一：上传事实资料（docx / pdf / txt）

1. 「本次事实资料」下方点**上传资料文件**，或多个文件一起拖进输入框
2. 服务端解析成纯文本后并入资料区，并注明来源文件名与解析方式
3. 解析优先级：`markitdown` → 标准库（docx 走 zip+xml，pdf 走 zlib 流解析）
4. 支持 `.docx .doc .dotx .pdf .txt .md .csv`，单文件上限 40MB

**注意**：扫描件 PDF 没有文本层，解析会失败并明确提示，此时请直接粘贴正文。

### 功能二：公众号链接入库（让智能体自己学习）

1. 在「语料入库」卡片粘贴链接，一行一个，可批量
2. 文体码可留「自动判断」，也可手动指定（STD / AVOID / HEALTH / SAFETY / MISC）
3. 点**抓取并入库** → 显示每篇结果（标题、文体、字数、写入的文件名）
4. 入库后**自动重算特征**，页面直接给出：语料篇数、篇幅分位、每条规则的实测频率与等级
5. 点**重建页面**把新语料同步到展示台

**服务端做了什么**：抓取（含 3 次重试）→ 提取正文 → 判文体 → 写入 `10_知识库/01_历史语料库/` → 重建 `语料清单.csv` → 重算 `_corpus_features.json` → 返回频率对照。

**两条纪律（已内置）**
- 入库文件头部恒为 `fact_usable: false` —— 只用于学风格，**永不作为写作事实**
- **单篇新样本不改规则**：同一新特征要在 ≥3 篇出现且与现规则冲突，才修订 KB2

### GitHub Pages 版本也能用

Pages 上的页面同样支持这两项——只要本机服务在运行。页面会把请求发到 `http://127.0.0.1:8787`（可在模型设置里改地址）。若提示连不上，就是服务没起。
