# 个人科普写作智能体 · 知识库与工作流

面向微信公众号科普写作的个人风格库。核心目标：**让 AI 写得像我、说人话、科普严谨**，且不会把旧文章里的标准和数据当成新事实。

> 语料：23 篇已发表推文（2025-11 → 2026-09）｜规则：R 级 9 条 + T 级 7 条 + 观察项 5 条｜变体：5 类

---

## 它解决什么问题

用 AI 写自己的风格，最容易踩三个坑：

| 坑 | 后果 | 本项目的对策 |
|---|---|---|
| 旧文章里的标准号、限值、日期被当成"本次可用事实" | 写出**过期数据**，而且看不出来 | 语料文件头部恒为 `fact_usable: false`；成稿每个数字必须能在**本次事实底稿**里找到已核验记录 |
| 让模型"参考"历史文章，结果变成洗稿 | 句子和独特比喻被搬走 | **写作节点不读历史原文**，只读规则卡；再叠加连续 12 字查重 |
| 让写作者自己检查自己的稿 | 自己查自己，形同虚设 | 三审各自**独立上下文**，只有否决权、没有放行权 |

同一套逻辑也写在系统提示词里：资料不足就**停工要料**，不写占位稿。

## 目录结构

```
├── 10_知识库/
│   ├── 01_历史语料库/      KB1 · 只读 · 仅风格（23 篇推文 + 台账）
│   ├── 02_风格规则库/      KB2 · 只读 · 写作唯一风格依据
│   ├── 03_本次事实资料库/  KB3 · 可写 · 每次写作一个 run
│   └── 04_评估与禁用库/    KB4 · 可写 · 禁用清单 + 评分卡
├── 20_工作流/              11 节点设计 + 系统提示词（完整版 / 压缩版）
├── 30_测试集/              12 个测试任务 + 评分卡 + 盲测方案
├── 00_交付文档/            审计报告、验收状态、部署说明
├── tools/                  工具链（见下）
└── docs/                   在线工作台（GitHub Pages 发布目录）
```

**四分区为什么必须分开**：KB1 只回答"我平时怎么写"，KB2 是写作时唯一的风格判决依据，KB3 是唯一的事实来源，KB4 管审校与黑名单。混用就会串味。

## 在线工作台

启用 GitHub Pages 后访问（`main` 分支 `/docs` 目录）：

- `https://<用户名>.github.io/<仓库名>/` —— **展示台**：规则、变体、语料检索、系统提示词一键复制
- `https://<用户名>.github.io/<仓库名>/writer.html` —— **写作台**：填选题 + 资料 → 七步流程 → 出成稿

写作台需要填自己的模型接口（OpenAI 兼容：DeepSeek / 通义 / 智谱 / Kimi / OpenAI 等），**API Key 只存在浏览器本地**。

若浏览器直连接口出现跨域错误，用本地小服务：

```bash
python tools/writer_server.py          # http://127.0.0.1:8787/writer.html
```

它会同时托管页面与转接接口（只监听 127.0.0.1）。

## 工具链

| 工具 | 用途 |
|---|---|
| `wechat_ingest.py` | 微信推文链接 → KB1 语料文件（含重试、图片语法清理、不破坏全角标点） |
| `corpus_digest.py` | 语料量化特征统计 —— **规则频率的唯一依据** |
| `kb_index.py` | 统一字数口径 + 修正文件头 + 重建 `语料清单.csv` |
| `build_site.py` | 生成展示台 `docs/index.html` |
| `build_writer.py` | 生成写作台 `docs/writer.html` |
| `writer_server.py` | 本地托管 + API 转接（解决跨域） |

### 常用命令

```bash
# 1. 入库一篇推文（链接抓取）
python tools/wechat_ingest.py "https://mp.weixin.qq.com/s/xxxx" \
  --out 10_知识库/01_历史语料库 --genre STD --date 2026-09-01

# 2. 重算统计（规则升级/降级的依据）
python tools/corpus_digest.py 10_知识库/01_历史语料库 --detail --json _corpus_features.json

# 3. 统一口径并重建台账
python tools/kb_index.py 10_知识库/01_历史语料库 --fix --csv

# 4. 刷新网页（知识库更新后必做）
python tools/build_site.py   --project . --out docs
python tools/build_writer.py --project . --out docs
```

## 规则等级制度

不靠印象定规则，靠频率：

| 等级 | 门槛 | 能否写进规则库 |
|---|---|---|
| **R** 稳定规则 | 同文体 ≥5 篇且无显著例外 | 可，默认执行 |
| **T** 倾向性规则 | 3–4 篇或存在例外 | 可，须标注"允许偏离" |
| **O** 观察项 | 1–2 篇 | **不可**，仅记录 |

**更新纪律**：单篇新样本只进 KB1、不动规则；同一新特征在 ≥3 篇出现且与现规则冲突，才修订 KB2 并记版本号。

### 一个真实的教训

「结尾必有来源模块」在 13 篇时看是 12/13（92%），像条硬规则；扩到 23 篇后变成 **STD 14/16、HEALTH 只有 3/6**。

如果当时就写死成"必须有"，AI 会给健康类文章硬加一个作者根本不会写的模块。所以现在这条规则**带文体限定**：只对 STD 生效。

同类修正还有：「标准引用三段式」从 4/4 降到 6/13（早期样本偏差）；篇幅从"1800–2200"两次修正到"1100–1800，目标 1300–1550"。

## 已知限制

- **变体 B（热点追踪，1 篇）、变体 E（慢生活，2 篇）样本不足** → 遇到这类主题须提示"风格样本不足"，不硬套
- 部分语料来自本地 docx（非权威版）；权威性优先级：**微信发布版 > 本地投稿稿**
- "像不像本人"尚未做盲测验证
- 三审独立性在写作台里通过"每步独立请求"实现；若改成单轮对话内自查，则会降级

## 发布与更新

仓库：<https://github.com/lbzzz-zhc/kepu-writing-agent>　·　网页：<https://lbzzz-zhc.github.io/kepu-writing-agent/>

```bash
git add -A && git commit -m "更新"
git push                                  # 网络正常时用这个
```

**若 `git push` 报连接失败**（本机环境下 `github.com:443` 不可达，但 `api.github.com` 正常），改用：

```bash
python tools/push_to_github.py --repo lbzzz-zhc/kepu-writing-agent --branch main --message "更新"
```

它以远端最新提交为父提交，逐文件走 REST API 推送，保留历史、不强制覆盖。

网页更新（改完知识库后必做）：重新跑 `build_site.py` / `build_writer.py` 生成 `docs/`，再提交推送，GitHub Pages 会自动重建（约 1 分钟）。
