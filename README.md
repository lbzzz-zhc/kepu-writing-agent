# 个人科普写作智能体 · 知识库与工作流

面向微信公众号科普写作的个人风格库。核心目标：**让 AI 写得像我、说人话、科普严谨**，且不会把旧文章里的标准和数据当成新事实。

> 语料：23 篇已发表推文（2025-11 → 2026-09）｜规则：R 级 9 条 + T 级 7 条 + 观察项 5 条｜变体：5 类

---

## 它解决什么问题

用 AI 写自己的风格，最容易踩三个坑：

| 坑 | 后果 | 本项目的对策 |
|---|---|---|
| 旧文章里的标准号、限值、日期被当成"本次可用事实" | 写出**过期数据**，而且看不出来 | 语料文件头部恒为 `fact_usable: false`；成稿每个数字必须能在**本次事实底稿**里找到已核验记录 |
| 让模型"参考"历史文章，结果变成洗稿 | 句子和独特比喻被搬走 | **写作节点不读历史原文**，只读规则卡；再叠加连续 12 字查重 |
| 让写作者自己检查自己的稿 | 自己查自己，形同虚设 | 三审各自**独立上下文**，只有否决权、没有放行权 |

同一套逻辑也写在系统提示词里：资料不足就**停工要料**，不写占位稿。

## 目录结构

```
├── 10_知识库/
│   ├── 01_历史语料库/      KB1 · 只读 · 仅风格（79 篇推文 + 台账）
│   ├── 02_风格规则库/      KB2 · 只读 · 写作唯一风格依据（规则表 v0.3 + 个人风格手册 + 证据表 + 变体手册 + 体检报告）
│   ├── 03_本次事实资料库/  KB3 · 可写 · 每次写作一个 run
│   └── 04_评估与禁用库/    KB4 · 可写 · 禁用清单 + 评分卡
├── 20_工作流/              11 节点设计 + 系统提示词（完整版 / 压缩版）
├── 30_测试集/              12 个测试任务 + 评分卡 + 盲测方案
├── 00_交付文档/            审计报告、验收状态、部署说明
├── tools/                  工具链（见下）
└── docs/                   在线工作台（GitHub Pages 发布目录）
```

**四分区为什么必须分开**：KB1 只回答"我平时怎么写"，KB2 是写作时唯一的风格判决依据，KB3 是唯一的事实来源，KB4 管审校与黑名单。混用就会串味。

## 在线工作台

启用 GitHub Pages 后访问（`main` 分支 `/docs` 目录）：

- `https://<用户名>.github.io/<仓库名>/` —— **展示台**：规则、变体、语料检索、系统提示词一键复制
- `https://<用户名>.github.io/<仓库名>/writer.html` —— **写作台**：填选题 + 资料 → 七步流程 → 出成稿 → **一键导出 Word 友好排版**

**成稿导出**：成稿带 Markdown 标记（`##`、`**`），直接粘 Word 会显示成符号。写作台提供三个出口：**复制「带格式」**（富文本，Word 里直接是标题+正文）／**复制纯文本**（清掉符号）／**下载 Word 文档（.doc）**。可切换首行缩进，并带排版预览。

写作台需要填自己的模型接口（OpenAI 兼容：DeepSeek / 通义 / 智谱 / Kimi / OpenAI 等），**API Key 只存在浏览器本地**。

### 两个需要本地服务的功能

浏览器出于安全策略不能读写磁盘、也不能跨域抓取微信链接，所以下面两件事必须由本机小服务代劳：

| 功能 | 说明 |
|---|---|
| **上传事实资料** | 写作台的「本次事实资料」支持上传 `docx / pdf / txt / md`，也可直接把文件拖进输入框；解析出的文本自动并入资料区 |
| **链接入库（让智能体学习）** | 粘公众号文章链接 → 一键抓取 → 写入 KB1 语料库 → 自动重算风格特征，页面直接显示频率变化与规则等级 |

```bash
python tools/writer_server.py          # http://127.0.0.1:8787/writer.html
```

它会同时托管页面、转接模型接口（绕开跨域）、解析文件、抓取入库、重算统计、重建页面。只监听 127.0.0.1。

### 怎么打开（挑一种）

**方式零：桌面图标（最省事）**

桌面已有三个图标，双击即用：**科普写作台（本地启动）** 会自动起服务并打开浏览器；**科普写作台（线上）**、**科普知识库（展示台）** 直接打开网页。

**方式一：双击启动脚本**

在仓库根目录双击 **`start-writer.bat`** —— 起服务 → 等端口就绪 → **自动打开浏览器**，一步到位。
（它调用的是 `tools/open_writer.py`；服务已在跑时会直接开浏览器，不重复启动。）

**方式二：命令行**

```bash
cd <仓库根目录>
python tools/writer_server.py
```

**方式三：换端口或换目录**

```bash
python tools/writer_server.py --port 9000
python tools/writer_server.py --site /path/to/docs
```

启动成功会看到：

```
科普写作台已启动
  写作台：http://127.0.0.1:8787/writer.html
  展示台：http://127.0.0.1:8787/index.html
  语料库：<工程目录>/10_知识库/01_历史语料库
  能力：模型转接 · 文件解析(docx/pdf) · 链接入库 · 统计重算 · 页面重建
```

**注意**
- 这个窗口**用完之前别关**，关掉服务就停，页面上的上传和入库会立刻失效
- 停止服务：在窗口里按 `Ctrl+C`
- `start-writer.bat` 优先用本机已装好解析库的 Python，找不到才退回环境变量里的 `python`
- 若 `python` 命令在你的终端里指向另一个没装 `markitdown` 的解释器，docx/pdf 解析会退化为标准库模式（docx 仍可解析，PDF 可能失败）

**入库纪律**：新文章只进 KB1（仅供风格）；同一新特征在 ≥3 篇出现且与现规则冲突，才改动 KB2。文章里的标准与数据**永远不作为**写作的事实来源。

### 可以装成应用（PWA）

两个页面都支持"安装到桌面/手机主屏"（Chrome/Edge 地址栏右侧的安装图标，或菜单里的"将页面作为应用安装"）。

**装成应用后内容照样改** —— 应用只是入口，东西还在 `docs/` 与 GitHub Pages 上：

```
改语料或规则 → 重跑 build_site.py + build_writer.py → 推送 → 刷新即新版
```

Service Worker 对**页面走网络优先**（保证刷新就能看到新版），跨域模型请求与本地 `/api/` 一律放行不缓存；缓存按版本号命名，旧版自动清理。检测到新版时右下角会浮出刷新提示。

图标由 `tools/pwa_assets.py` 用纯标准库生成（手写 PNG，不依赖 Pillow）。

### 改稿体检

写作台顶部两个模式：**写新稿** / **改稿体检**。改稿 = ①体检（本地对照 KB2 与文体手册，可复算）→ ②按手册改稿（模型一次请求）→ ③再体检 + 改前改后对照。

- 体检阈值全部从 KB2 规则表解析，**不在页面里写死**
- 文体自动判定只作建议（68–71% 准确），显示置信度、可手动改判
- 改稿硬约束：标准号/数值/限值/日期/结论一律不动，不新增事实，不删实质信息
- 查重：`/api/dupcheck` 与 KB1 做连续 12 字比对（G3 硬闸）

### 只要纯文本，不要配图

语料是用来学**写法**的，配图和图注都是噪音。入库时一律转成"排版好的纯文本"：

- **去图**：`<img>` / `[[图片]]` / `![](data:image...)` 全部删除，不占位
- **去图注**：图片版权行（`图片来源：…`）与"标准号：指标名"式图注删除
- **还原小标题**：微信正文的小标题是整行加粗（没有 `<h1>`），提取时还原成 `**小标题**`
- **折叠重复标记**：嵌套加粗产生的 `****x****` 归一为 `**x**`

**判定图注要保守**。曾经用"短 + 不以句号结尾 + 紧邻图片"判定，结果把 `选购注意事项`、`认清标准` 这类真实小标题误删了——微信排版里小标题后面紧跟图片很常见。现在只认三条强特征（版权署名 / 标准号开头且后接冒号 / 以"见图"收尾）。

## 工具链

| 工具 | 用途 |
|---|---|
| `wechat_ingest.py` | 微信推文链接 → KB1 语料文件（含重试、**去图去图注**、还原加粗小标题、不破坏全角标点） |
| `corpus_digest.py` | 语料量化特征统计 —— **规则频率的唯一依据** |
| `kb_index.py` | 统一字数口径 + 修正文件头 + 重建 `语料清单.csv` |
| `kb_clean.py` | 清洗语料：删图片标记、图注与孤立符号行，只留排版好的纯文本（带备份与预演） |
|  `build_site.py` | 生成展示台 `docs/index.html` |
| `build_writer.py` | 生成写作台 `docs/writer.html` |
| `writer_server.py` | 本地托管 + API 转接 + 文件解析 + 链接入库 + 统计重算 + 查重(12字)（**网页用，可选**） |
| `check_draft.py` | **改稿体检（命令行）** —— 本地算、口径与网页同源，对话内可直接跑 |
| `dupcheck.py` | **G3 查重（命令行）** —— 与 KB1 连续 12 字比对，命中列出源篇目 |
| `style_report.py` | 风格体检报告（9 节，含时间分层）—— KB2 规则频率的唯一来源 |
| `open_writer.py` | 一键起本地服务并打开浏览器 |
| `push_to_github.py` | 经 REST API 增量推送（本机 `git push` 不可用时的通道） |

### 两条运行路线（读同一份 KB2，结论一致）

| | 对话内直跑（推荐） | 网页版 |
|---|---|---|
| 写稿 | 本会话模型 | 需自备 API Key |
| 三审独立 | **独立子代理，真隔离** | 三次独立请求 |
| 体检 / 查重 | `check_draft.py` / `dupcheck.py` | 页面按钮（同一套逻辑） |
| 需要开服务 | 否 | 是（上传文件、入库） |
| 适合 | 日常写稿、改稿 | 界面化操作、给同事用、装成 App |

### 常用命令

```bash
# 1. 入库一篇推文（链接抓取）
python tools/wechat_ingest.py "https://mp.weixin.qq.com/s/xxxx" \
  --out 10_知识库/01_历史语料库 --genre STD --date 2026-09-01

# 2. 重算统计（规则升级/降级的依据）
python tools/corpus_digest.py 10_知识库/01_历史语料库 --detail --json _corpus_features.json

# 3. 统一口径并重建台账
python tools/kb_index.py 10_知识库/01_历史语料库 --fix --csv

# 3b. 清洗历史语料里的图片与图注（先预演，再加 --apply）
python tools/kb_clean.py 10_知识库/01_历史语料库
python tools/kb_clean.py 10_知识库/01_历史语料库 --apply

# 4. 刷新网页（知识库更新后必做）
python tools/build_site.py   --project . --out docs
python tools/build_writer.py --project . --out docs
```

## 规则等级制度

不靠印象定规则，靠频率：

| 等级 | 门槛 | 能否写进规则库 |
|---|---|---|
| **R** 稳定规则 | 同文体 ≥5 篇且无显著例外 | 可，默认执行 |
| **T** 倾向性规则 | 3–4 篇或存在例外 | 可，须标注"允许偏离" |
| **O** 观察项 | 1–2 篇 | **不可**，仅记录 |

**更新纪律**：单篇新样本只进 KB1、不动规则；同一新特征在 ≥3 篇出现且与现规则冲突，才修订 KB2 并记版本号。

### 一个真实的教训

「结尾必有来源模块」在 13 篇时看是 12/13（92%），像条硬规则；扩到 23 篇后变成 **STD 14/16、HEALTH 只有 3/6**。

如果当时就写死成"必须有"，AI 会给健康类文章硬加一个作者根本不会写的模块。所以现在这条规则**带文体限定**：只对 STD 生效。

同类修正还有：「标准引用三段式」从 4/4 降到 6/13（早期样本偏差）；篇幅从"1800–2200"两次修正到"1100–1800，目标 1300–1550"。

## 已知限制

- **变体 B（热点追踪，1 篇）、变体 E（慢生活，2 篇）样本不足** → 遇到这类主题须提示"风格样本不足"，不硬套
- 部分语料来自本地 docx（非权威版）；权威性优先级：**微信发布版 > 本地投稿稿**
- "像不像本人"尚未做盲测验证
- 三审独立性在写作台里通过"每步独立请求"实现；若改成单轮对话内自查，则会降级

## 发布与更新

仓库：<https://github.com/lbzzz-zhc/kepu-writing-agent>　·　网页：<https://lbzzz-zhc.github.io/kepu-writing-agent/>

```bash
git add -A && git commit -m "更新"
git push                                  # 网络正常时用这个
```

**若 `git push` 报连接失败**（本机环境下 `github.com:443` 不可达，但 `api.github.com` 正常），改用：

```bash
python tools/push_to_github.py --repo lbzzz-zhc/kepu-writing-agent --branch main --message "更新"
```

它以远端最新提交为父提交，逐文件走 REST API 推送，保留历史、不强制覆盖。

网页更新（改完知识库后必做）：重新跑  `build_site.py` / `build_writer.py` 生成 `docs/`，再提交推送，GitHub Pages 会自动重建（约 1 分钟）。
