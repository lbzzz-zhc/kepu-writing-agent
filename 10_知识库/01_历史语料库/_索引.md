# KB1 · 历史语料库

## 一句话定位
**只回答"我平时怎么写"，绝不回答"XX 标准限值是多少"。**

## 收录范围
| 采纳 | 本人独立署名 / 第一署名、完整正文（净字数 ≥800）、有发布日期、面向大众 |
| 降权（标注 `diluted: true`） | 合作稿、访谈稿、经编辑大改的约稿；非目标领域的文章 |
| 剔除 | 转载、汇编、榜单速览、图片承载主要信息导致正文残缺、软广 |

## 文件命名
`KB1-<文体码>-<YYYYMM>-<序号>_<短标题>.md`

文体码：`STD` 标准与热点解读 · `AVOID` 消费避坑 · `HEALTH` 健康与营养 · `SAFETY` 产品安全使用 · `MISC` 其他

示例：`KB1-STD-202608-07_安全帽新国标.md`

## 每个文件必须带的头部字段
```yaml
---
id: KB1-STD-202608-07
title: 文章标题
published: 2026-08-15          # 必须准确
word_count_net: 1860           # 正文净字数（去标题、来源、二维码引导）
genre: STD
byline: 独立              # 独立 / 第一署名 / 联合 / 编辑部
original_mark: true        # 是否带原创标
diluted: false             # 是否为合作/约稿等风格被稀释的稿件
parse_quality: 完整        # 完整 / 缺段 / 仅图片
source_label_style: "据××发布"   # 原型记录你标注来源的习惯措辞
fact_usable: false         # 恒为 false —— 这是防串味的硬约束
---
```

## 三条禁令
1. **禁止**作为事实来源（`fact_usable: false` 恒为 false，不允许例外）。
2. **禁止**在"生成正文"节点被整篇读入上下文；此阶段只允许使用 KB2 的规则卡。
3. **禁止**把同一篇文章的草稿与发布稿都入库（只留发布稿，避免同一篇被算作 2 篇依据）。

## 配套文件
- `语料清单.csv` —— 已入库语料的审计台账（每入库一篇追加一行）
- `语料清单_模板.csv` —— 空白模板
- `../_raw_原始转换/` —— docx 转 Markdown 的原始转换件，供溯源比对

## 入库方式（三种，免手工整理）
| 方式 | 命令 / 做法 | 说明 |
|---|---|---|
| 链接自动抓取 | `python tools/wechat_ingest.py "<mp.weixin.qq.com 链接>" --out <本目录> --genre STD --date YYYY-MM-DD` | 首选，详见《链接入库使用说明》 |
| 本地文件转换 | `python tools/wechat_ingest.py --file <xxx.md> --out <本目录>` | 已导出文档时用 |
| 纯文本粘贴 | 复制正文粘给智能体 | 抓取失败时的兜底 |

入库后必须：核对日期（缺失就问，不许猜）→ 定文体码 → 追加一行到 `语料清单.csv`。

## 字数口径（三处必须一致）
`正文净字数 = 全文 − 空白 − [[图片]] 占位 − 图注行 − 来源清单及其后所有行`
> 已修正过的坑：早期版本把图片标记与来源清单计入字数，导致虚高 200–300 字；且曾用 NFKC 归一化把全角标点压成半角。两者均已修复并全库重算。

## 入库时的清洗项
1. **标点**：原文用**全角**（实测全角逗号 644 : 半角 1），不得做 NFKC 归一化
2. **docx→md 噪音**：`![](data:image...)` 必须在入库前清除
3. **图载信息**：图片 >20 张的篇目 `parse_quality` 标"图载信息偏高"，**不从该篇推断版面规律**
4. **日期**：抓不到必须问用户，不许猜
5. **同题多版本**：标 `variant_of` + `counted: false`，不得重复计入频率
