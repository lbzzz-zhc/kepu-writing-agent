## 规则表内容概览（v0.3）

**R 级 4 条**（默认执行，无条件）
- R-01 开篇只写场景，段内不出现标准号与"标准/规定"字样 —— 100% / 96%
- R-02 几乎不用感叹号（全篇 0 个）—— 92%
- R-03 正文必须落到具体标准（≥1 个带编号）—— 99%
- R-04 每篇必有来源标注（独立模块 **或** 行内"内容来源：xxx"）—— 81%

**T 级 7 条**（默认执行，允许偏离）
- T-01 加粗短句切节，篇均 6 个小标题（问句式 71%，STD 85%）｜T-02 标题习惯（16.9 字、带问号 59%）
- T-03 篇幅 **1000–1400 字（中位 1180）**｜T-04 段落节奏（20 段、段长 57 字）
- T-05 术语双层写法｜T-06 连接词与过渡（可能 53%／通常 46%／因此 43%）｜T-07 称谓（消费者为主）

**O 级 5 条**（仅观察，不注入）：emoji 锚点 39%｜竖线标题 11%（系列内 9/9）｜箭头收尾 6%｜时令开篇 29%｜来源模块名可变

## 注入位置（已改为自动生成）

系统提示词 `第 10 条 · 风格规则注入区`，位于 `<<<KB2_RULES_START>>>` 与 `<<<KB2_RULES_END>>>` 之间。

**同步命令**（规则表更新后必须执行）：
```bash
python tools/build_site.py --project . --out docs --sync-prompt
```
它会从 KB2 主表 + 文体变体手册**重新生成**注入区并写回提示词。
→ 注入区不再手写，杜绝"提示词还是 v0.2、知识库已是 v0.3"这类漂移。

## 页面数据也是解析来的

`build_site.py` 通过 `load_rule_table()` 直接解析 KB2 主表，规则不再硬编码在脚本里。
解析失败的兜底副本保留在 `RULES_*_FALLBACK`，并在构建日志里报警。

## 更新纪律
- 新增单篇样本 → **只进 KB1**，不动本库
- 同一新特征在 **≥3 篇**出现且与现规则冲突 → 才修订规则表，并升版本号
- 规则频率一律以 `tools/style_report.py` 实测为准，**不得凭印象**
- 升版后**必须**跑一次 `--sync-prompt`，否则提示词与库不一致
